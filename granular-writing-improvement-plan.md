# Plan: Granular Writing Improvement (Diff-Based Application)

## 1. Problem Statement

Currently, the "Improve Writing" feature replaces the entire selected text (or document) with the AI-improved version.

- **Issue**: If the user has "Track Changes" enabled in Word, this action appears as "Deleted entire paragraph" + "Inserted entire new paragraph".
- **Consequence**: The user loses context of what specifically changed (words, grammar, punctuation), making review difficult.
- **Goal**: Apply changes granularly so that Word's **Track Changes** feature (or the user's visual review) highlights only the specific words that were modified (e.g., Red Strikethrough for deletions, Blue/Underline for insertions).

## 2. Proposed Solution

Instead of a bulk replace, we will implement a **Diff-Based Application Strategy**.
We will utilize the `diffMarkup` (already generated by the AI for the preview) to drive a series of precise edits in the Word document.

### 2.1. detailed Workflow

1.  **Generate Diff**: The AI returns the improved text with markup, e.g., `I <remove>declare</remove><add>certify</add> that...`.
2.  **Parse Diff**: Convert this markup into a structured list of operations.
3.  **Execute Edits**: Iterate through the operations and apply them to the Office.js `Range` object sequentially.

## 3. Technical Implementation Plan

### Step 1: Diff Parser Utility (`utils/diffParser.ts`)

Create a helper to transform the XML-like diff string into an operation queue.

**Input**:
`"I <remove>declare</remove><add>certify</add> under penalty..."`

**Output (Operations Queue)**:

```json
[
  { "op": "match", "text": "I " },
  { "op": "replace", "original": "declare", "modified": "certify" },
  { "op": "match", "text": " under penalty..." }
]
```

### Step 2: Granular Application Logic (`services/wordService.ts`)

Implement a new function `applyDiffToSelection(operations: DiffOperation[])`.

**Algorithm**:

1.  Get the current `Selection` range.
2.  Iterate through the _Operations Queue_.
3.  **For `match` ops**:
    - Search for the text matches to confirm we are at the right place (optional validation) or simply advance our "search cursor".
    - _Crucial_: In Office.js, we might simply skip these, but we need to ensure we don't accidentally replace the wrong instance of a repeated word.
    - _Better Strategy_: Use a "consumer" approach. Search for the pattern of the _entire_ text block to map the ranges, then apply edits to the sub-ranges.
4.  **For `replace` / `delete` / `insert` ops**:
    - **Replace**: Search for `original` text within the remaining scope of the selection. Get the first match. Use `range.insertText(modified, "Replace")`.
    - **Delete**: Search for `original`. `range.delete()`.
    - **Insert**: Insert text at the current cursor position (end of previous match).

**Ambiguity Handling Strategy** (Handling repeated words):

- We will split the original paragraph by the _original text_ of the changes.
- Using `range.search(searchText, { matchWildcards: false })`, we get a collection of ranges.
- We strictly iterate through them in order, applying the corresponding edit from our Diff Queue.

### Step 3: Frontend Integration (`views/ActionsView.tsx`)

Update `handleApplyImprovement`:

1.  Check for `improvementResult.diffMarkup`.
2.  If available, call `wordService.applyDiffToSelection(improvementResult.diffMarkup)`.
3.  Fallback: If diff parsing fails or is too complex for the specific text structure, revert to the legacy full-replace method.

## 4. Expected User Experience

- **Scenario**: User selects "I declare under penalty...".
- **Action**: User clicks "Improve". AI Suggests changing "declare" to "certify".
- **Result**:
  - The Preview shows the change visually.
  - Upon clicking "Apply", the Word document updates.
  - If "Track Changes" is ON: "declare" turns Red/Strikethrough, "certify" appears in Blue/Underline.
  - If "Track Changes" is OFF: The text simply updates, but the document history (Undo/Redo) treats it as a specific edit rather than a full overwrite.

## 5. Prerequisite: AI Service Format

Ensure `services/aiService.ts` consistently returns the `diffMarkup`.

- _Status_: It currently does (`<remove>`/`<add>` tags).
- _Action_: No change needed in AI Prompt, just ensure the parser handles edge cases (e.g. whitespace inside tags).
